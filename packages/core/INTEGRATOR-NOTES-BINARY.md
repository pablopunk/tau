# Core owner: notes for the integrator and the CLI owner

- `CreateCoreOptions.cliEntry` is gone. The CLI passes `cliCommand: cliEntry()` (`{ command, args }`) and, when compiled, `assets: { versionDir }`.
  `packages/cli/src/run.ts:78` (`cliEntry: dependencies.cliEntry`) and `serve.ts:69` still use the old option, so `pnpm check` fails there until the CLI owner switches. That is the only check error.
- `claude-cli/service.ts` (not in core's list) lost `createNpmSdkInstaller`; its default installer is now `noopSdkInstaller` (two lines). `installClaudeCliSdk` in the providers API still exists and now does nothing but refresh; the web owner can drop the "install SDK" button copy.
- SDK: `provider-service` passes `sdkHome = <versionDir>/claude-sdk` when `assets` is set. `sdk-port` imports `<sdkHome>/node_modules/@anthropic-ai/claude-agent-sdk/sdk.mjs` by file URL when that file exists (no `createRequire`), else falls back to the old resolution (dev).
- `authStatus` picks, in order: `TAU_CLAUDE_PATH`, the SDK's native `claude` (`<sdkHome>/node_modules/@anthropic-ai/claude-agent-sdk-*/claude`), the `claude` on `PATH`. With none, the existing detector maps the ENOENT to state `missing`. `claude --version` (`claude-cli-version.ts`, not core's list) still reads `TAU_CLAUDE_PATH`/`PATH` only: on a node with no `claude` installed `cliVersion` is null while `sdkCliVersion` is set. Acceptable; change that file if you want the sidecar there too.
- Terminals: `createCore` builds the default daemon with `<versionDir>/pi-env`. Skills: `createCore` calls `useBundledSkills(versionDir)`, so the builtin skill is read from `<versionDir>/skills/tau/SKILL.md` (a module-level setting, because the prompt section in `harness/coding-extension.ts` calls `discoverSkills(cwd)` directly). The build script must copy `skills/builtin/tau/SKILL.md` to `<versionDir>/skills/tau/SKILL.md`.
