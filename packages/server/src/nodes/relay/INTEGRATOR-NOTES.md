- **Capabilities.** The relay only floods to links whose `hello.capabilities` list `announce` and only forwards over `relay`. With `NODE_CAPABILITIES = []` nothing is relayed (Step 1 behaviour). Flip it to `STEP2_CAPABILITIES`. The tests here add the capabilities by wrapping `core.nodes.self` (`test-chain.ts`).

Executable versions live here: r2 (`relay-rules.test.ts` "r2"), r4 credit/ready/id rewrite/60 s 1013/close propagation (`relay-rules.test.ts` "r4", `relay-chain.test.ts`), r6 tombstone closes streams and expel floods before 4003 (`relay-chain.test.ts` "tombstones and expels"), r7 window, replay, skew (`relay-rules.test.ts` "r7"). Replace the `it.todo`s with a pointer or delete them.
- **Group peer ids are `nodeId`s** in every `NodeGroup` call (`linkUp`, `acceptAnnounce(frame, from)`, `route().nextHop`). The relay looks `nextHop` up with `registry.linkOf(nextHop)` (links are keyed by `nodeId`).
- **Registry seam.** `LinkRegistry` gained `links()`, `linkOf()` and `hub` (set by `createRelay`); `RegisteredLink` gained `capabilities`, `mux`, `sendFrame`. `NodeGateway.isOnline/request/openStream` fall back to the hub (`group.route`) when the node is not a direct link; with no route the error stays `not_found` ("offline"), a hop that lost its route answers `no_route`.
- **Signing.** `headerPayload` (`relay/header.ts`) repeats the canonical text of `signRequestHeader` because the key never leaves core (`core.nodes.sign`). Suggest exporting a `requestPayload(...)` from `protocol/identity/request-header.ts` and using it from both. An `open` signs `method = ""`, no content type, no body.
- **Trail.** The origin sends `trail: [origin]`, `ttl: 16`; each relay appends itself and decrements. A relay requires `trail.at(-1) === link.nodeId` and `origin === trail[0]`.
- **Clock hook.** `TAU_FAKE_CLOCK_OFFSET_MS` is read once by `createRelay` (`relay/clock.ts`) and shifts only routed-header signing and verification. Set it before starting the server (e2e r7).
- **Expel handling.** After a fresh expel from the wire: flood first, then the link to the target closes 4003 with `bye` and every stream with that origin closes. A node that learns it was expelled (`selfExpelled`) keeps its links. `floodExpel` also calls `core.nodes.forget(target)`. Owner E's `onTombstone` is used to close streams only; links are cut by the expel path so the target hears why.
- **Unsynced and announces.** The relay sends `expel-sync` then its announce on link-up; `markUnsynced` fires after 10 s without the peer's `expel-sync`. It does not drop announces itself: core refuses them (`unsynced`).
- **Flap guard** was already in `link-registry.ts` (three reconnect replacements per minute, 4002 "duplicate identity"); `hello` of a tombstoned id closes 4003 in `link-peer.ts`.
- `relay/test-chain.ts` is a helper for three real servers with a steerable `NodeGroup`; the real-core integration (three cores via `attachPeer`) is still the integrator's.
